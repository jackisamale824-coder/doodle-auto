How Doodle Auto works

Your browser moves your character immediately. In multiplayer, a game server decides what everyone shares. Sign in and your match history stays with you after the room closes.

One move in a shared match

  1. You press forward

    Rapier checks local collisions. The camera moves this frame, and the client sends the new pose over its open WebSocket.

  2. The room checks the move

    The server checks travel distance and obstacles. It can send a correction. The room advances shared actors and game rules on a 30 Hz tick.

  3. Other players see you move

    The server sends snapshots. Each browser smooths remote movement between updates and draws the next frame with Three.js.

Inside the system

What changes between solo and multiplayer?

Solo. The browser runs the world simulation. Free roam lets you explore. District runs add rivals and objectives. In the City Archive, clearing six rivals and collecting three rooftop marks opens the return route to spawn.

Online. The menu reads the lobby list over HTTP. A WebSocket connects you to a public game, a duel or a private room by invite code. The welcome message supplies the room seed and spawn. Public Rust rooms run waves of rivals. County rooms share cars and citizens. Duels end at 15 eliminations.

During play. A room owns health, ammunition, hits and score. The client can show immediate feedback while the server resolves the outcome. Compact snapshots keep players in view of one another and prioritize nearby NPC and vehicle updates between full refreshes.

How do both sides agree on the map?

Browser and server call the same level builder with the same seed. The browser uses the geometry for rendering and physical movement. The server indexes it for movement checks, lines of sight and hit detection.

Rust uses prepared oil-yard collision geometry and navigation points. City Archive generates streets, parcels, buildings and traversal routes from a seed. Switchback County adds roads, enterable buildings, cars, citizens and breakable structures. A joining player receives the room’s current changes, including damaged structures and rubble.

What survives after you leave?

On this browser. You can enter with a guest nickname saved for the tab session. Local storage remembers settings, loadout and personal best. In the room. Player positions, live vehicles, NPCs and damaged buildings belong to the running match. Starting a new room rebuilds the world.

In your account. Password or Google sign-in establishes a session cookie. The server associates the connection with your profile and periodically saves online play time, kills and deaths. An eligible completed duel between two signed-in opponents updates their Elo ratings.

In production, the account API and match recorder send database commands through a private Worker entrypoint to SQLite. The same commands use a local SQLite file in development.

How does a change reach sully6.com?

Push → check → build → deploy → verify. A push to main starts GitHub Actions. It checks the game and Worker types, tests networking and accounts, then builds the browser assets with Vite. Cloudflare rolls out the Worker and the Docker image containing the game server and assets.

The final check compares the live client bundle with the build and connects to a County room to confirm that production sends the expected multiplayer snapshot.
